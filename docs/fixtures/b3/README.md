# B3 fixtures

All response fixtures are generated by real Django/PostgreSQL test calls with synthetic records.
Telegram and storage transports are mocked. They are not seed data or production economy.
Independent fixture files may represent different synthetic worlds, config versions and players.
Do not combine their numeric IDs/cursors into one real account history.

| File | Source / meaning |
|---|---|
| `openapi.json` | Actual implemented Ninja routes and transitive schemas; `scripts/export_b3_openapi.py --check` is a CI gate |
| `earn-network.json` | Exact authenticated HTTP Daily/Mission/Typing/Referral/Network/canonical/Bootstrap/Profile requests and responses |
| `creator-network-active.json` | Real activity engine receives three synthetic speakers, settles once, then serves actual group metrics |
| `errors.json` | Actual missing-auth, unavailable mission, missing idempotency key, foreign attempt and restricted Daily errors |
| `session-switch.json` | PostgreSQL initial acquisition, another owner, explicit switch and moved-device snapshots |
| `session-recovery-latency.json` | 20 local service-transaction samples per recovery scenario; no WAN/WebView claim |
| `banners.json` | Approved upload-backed active banner and explicit empty result |
| `start-welcome.json` | Approved English HTML text and genuine Web App + Community keyboard options |
| `broadcast-audiences.json` | Independent actual users/groups estimates, materialization and sent counts |
| `broadcast-retry-local_rate_limited.json` | Internal admission refusal → RETRY_WAIT for both target kinds |
| `broadcast-retry-rate_limited.json` | Telegram 429-class response + retry_after → RETRY_WAIT |
| `broadcast-retry-budget_unavailable.json` | Temporary budget outage → RETRY_WAIT without permanent failure |
| `broadcast-cancel-uncertain.json` | Cancel preserves an expired dispatch reservation as UNCERTAIN and skips pending targets |

To regenerate test fixtures, run the relevant `test_b3_*` modules with
`B3_EXPORT_FIXTURES=1`; serialize pytest invocations sharing the same test database. Runtime UUIDs,
timestamps and IDs may vary. Never regenerate historical economic ledgers/config snapshots.
