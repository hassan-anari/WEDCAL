## Findings and corrections

1. **Pinned cooldown duration was missing.** `LeaseOutput.cooldown_seconds` is now returned from the immutable lease/burst policy in every matching-session snapshot. It is distinct from absolute nullable `snapshot.cooldown_until`. Publication regression changes policy from 10s to 23s during a 50-tap burst: existing authorization stays 10s, completion sets the original deadline, next burst receives 23s.
2. **Snapshot ordering was valid, but did not identify acknowledged requests.** `(receipt_cursor, revision)` remains the authoritative lexicographic ordering within the verified player/Season scope. Daily/Missions can advance the all-source ledger cursor without changing Tap revision. The authenticated JSON regression demonstrates Daily claiming during an active lease and refreshing balances with unchanged Tap state. A PostgreSQL concurrency regression observes actual `pg_blocking_pids` waiters while Daily has uncommitted ledger/projection writes: Tap state waits for that commit and returns a coherent cursor/balance pair.
3. **Recovery evidence is now explicit and typed.** Every batch success adds `receipt`, reconstructed from existing immutable RewardLedger request/receipt metadata, ledger ID, source time, Season and config. It identifies the original idempotency key, lease/session/generation, requested range and exact accepted/rejected counts. Existing flat fields are preserved. Delayed receipts are processed separately from stale snapshots. Lost partial-response recovery uses only the original persisted request; replays after lease expiry, revocation or metadata purge return identical evidence with fresh state and no additional ledger writes. Changed body/same key returns `IDEMPOTENCY_CONFLICT`. No receipt is invented from a cursor/sequence or a terminal error. No new receipt table, backfill or migration is needed.
4. **Avatar requests bypassed shared Bot API budgeting.** Existing global/method Redis counter keys are now used by both Bot API transports. Avatar methods and file downloads reserve that shared budget before DNS/network and fail closed on budget-store loss. HTTP/JSON 429 responses from either transport atomically extend a shared bot-wide pause; shorter concurrent replies cannot shorten it. Existing critical Bot API calls retain their prior fail-open behavior on Redis failure. No independent avatar API allowance was added.
5. **Avatar concurrency/retries needed coordination.** PostgreSQL session advisory slots bound simultaneous refresh operations across worker processes (default 2, configurable 1–16). All workers must use the same setting and budget namespace; direct/session-pooled PostgreSQL is required. Unavailable slots defer work without sleeping. Refresh failures persist the greater of the local retry minimum and Telegram retry delay, plus configured jitter. Changed photo metadata/Bootstrap cannot bypass pending error backoff. Source/MIME/size/redirect/SSRF/privacy checks and fallbacks remain intact.
