# Separately authorized post-merge performance phase

The owner explicitly sequenced this work after independent review and an authorized merge of
PR #38. No merge, deployment, performance-phase execution or Production load is authorized here.
Functional completion is not a capacity certificate. The historical measurements in CAPACITY.md
remain useful baseline evidence at their recorded implementation hashes.

The later phase must pin the merged runtime, migrations, policy/config profiles and infrastructure,
then use disposable PostgreSQL and the actual supporting services with realistic canonical producers.
Registered, weekly active and qualified populations must be reported separately.

Deferred scope:

* sustained full-source Typing/Mission/Clan/Creator/referral production and recognition;
* large correction cohorts and complete Season Close, including residual/ledger reconciliation;
* million-user concurrent ordinary traffic with economic workers and the alert scanner running;
* history-heavy Admin queries and many-Season table/index growth;
* SQL plans, row counts, WAL/checkpoints, locks/waits, CPU/RSS, queue arrival/backlog/catch-up,
  parallel-worker throughput, contention/retry/failure rates and end-to-end Epoch latency;
* repeated sparse/mixed/concentrated/adversarial workloads, late/deferred/moderated users,
  worker/broker/database restart and recovery;
* actual durable-storage resource sizing and optimistic/base/conservative capacity bounds, with
  uncertainty and explicit next validation tiers instead of an unsupported linear readiness claim.

Existing scripts remain opt-in and separate from routine CI. The operator must explicitly designate
disposable test resources. No benchmark may target Production, real balances or live notifications.
Performance acceptance, infrastructure provisioning and release/activation remain owner decisions.
